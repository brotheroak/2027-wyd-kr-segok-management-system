# 분과 협업

독립된 **분과 협업** 공간(`/workspace`)에서 회의록, 후속 업무, 문서, 채널 대화를 함께 관리합니다. 운영자 콘솔과 분리된 화면·메뉴·로그인을 제공하며, 기존 계정과 로그인 세션 및 DB를 함께 사용합니다. 이전 `/admin#collaboration` 주소는 새 공간으로 연결됩니다.

## 구성원 시작하기

1. `/workspace` 또는 채팅 바로 입장 주소 `/chat`에서 **분과 구성원 가입 신청**을 선택합니다. 홈페이지 메뉴에는 협업 링크를 추가하지 않습니다.
2. 슈퍼 관리자가 기존 계정 관리 화면에서 가입을 승인합니다.
3. 승인된 구성원은 협업 공간에서 로그인해 분과 협업과 비밀번호 변경을 사용할 수 있습니다. 운영자 콘솔에서 분과 구성원으로 로그인해도 협업 공간으로 이동합니다. 신청자·봉사자 개인정보, 위치 이력, 계정 관리 API는 사용할 수 없습니다.

기존 일반 운영자, 개인정보 관리자, 슈퍼 관리자도 협업 기능을 사용할 수 있습니다. 기본 설정에서는 구성원이 모든 분과를 읽고 작성할 수 있습니다. 운영자는 **분과 권한**에서 지정 구성원 전용 분과와 읽기 전용 구성원을 설정할 수 있습니다. 전용 분과의 기록·대화·파일은 지정 구성원과 운영자만 접근할 수 있습니다. 공통 회의 정보와 전체 채널은 공유됩니다.

## 회의록과 후속 업무

새 회의를 만들면 총괄, 대외협력(재정), 홈스테이, 교육, 청소년, 시설, 전산, 회계의 기록이 자동 생성됩니다. 각 기록에 작성자, 진행사항, 상호협조(논의)사항, 협조 요청 팀, 결정 사항, 향후 계획을 적습니다. 공동회의록과 작성 현황은 저장된 분과 기록에서 자동 취합됩니다.

후속 업무에는 담당 분과, 담당자, 기한, 상태와 연결 회의를 지정할 수 있습니다. 상태는 할 일·진행 중·완료입니다. 다른 구성원이 먼저 수정한 기록은 덮어쓰지 않고 최신 내용을 확인하도록 안내합니다.

회의를 선택한 뒤 **기존 양식 엑셀**을 누르면 원본 양식의 작성안내·공동회의록·8개 분과 시트가 있는 `.xlsx` 파일을 내려받습니다. 색상, 병합 셀, 분과 취합 수식과 인쇄 방향을 유지하며 선택한 회의에 연결된 후속 업무도 포함합니다. 업무가 8개를 넘으면 행을 늘립니다. 내려받은 파일을 Excel에서 열어 검토·수정·인쇄할 수 있습니다. Excel에서 수정한 내용은 웹사이트에 자동으로 저장되지 않습니다.

## 문서와 대화

문서함은 제목·분과·본문을 저장하고 간단한 제목 및 목록 표기를 표시합니다. 첨부 파일은 파일당 12 MiB까지 업로드할 수 있으며 해당 분과의 읽기 권한이 있는 로그인 구성원만 다운로드할 수 있습니다. 업로드 자료는 서버의 임시 디스크 대신 기존 DB에 암호화해 저장합니다.

전체 채널과 8개 분과 채널에서 대화 및 답글을 작성합니다. 메시지와 답글에 파일당 12 MiB, 메시지당 5개까지 첨부할 수 있습니다. 글 없이 파일만 보낼 수도 있습니다. 파일은 먼저 업로드하고 보내기로 메시지에 연결하며, 초안에서 첨부를 취소해도 업로드된 원본은 문서함에 보관됩니다. 채팅 첨부는 업로드 시 해당 채널의 분과 권한을 적용합니다. 전용 분과에 올린 파일은 다른 채널에 다시 첨부할 수 없습니다. 문서함 업로드는 현재 선택한 분과에 보관합니다. 화면이 보이는 동안 15초마다 최신 기록을 가져옵니다. 사이트 내 알림을 지원하며 실시간 WebSocket, 기기 푸시 알림, Slack/Notion 계정 연동은 포함하지 않습니다.

## 기존 기록 가져오기와 백업

일반 운영자 이상은 **백업 가져오기**에서 `wyd-collaboration-v1` 형식의 JSON 파일을 선택할 수 있습니다. 이전 협업 사이트의 **기록 백업** 파일 또는 변환된 회의록 파일을 사용합니다. 모든 기록을 검증한 뒤 한 번에 저장하며, 이미 존재하는 기록 번호가 있으면 덮어쓰지 않고 가져오기를 거절합니다. 각 신규 회의에는 서로 다른 8개 분과 기록이 필요합니다.

구성원은 기록 백업 JSON과 회의록 CSV를 내려받을 수 있습니다. JSON 백업에는 회의록·업무·문서·대화가 포함되며 첨부 바이너리는 포함되지 않습니다. 첨부는 문서함 또는 대화에서 별도로 다운로드합니다. 파일 바이너리가 없는 다른 공간으로 첨부 메시지 백업을 가져오는 것은 거절합니다. 기존 사이트와 자동으로 동기화하지 않으므로 전환 시 한 시스템을 공동 작성 공간으로 정해야 합니다.

첨부된 실제 회의록과 개인 명단은 공개 저장소에 포함하지 않습니다. 새 설치는 빈 협업 공간으로 시작하며 운영자가 로그인한 뒤 기록을 가져옵니다.

## 설치와 배포

기존 환경 변수와 실행 절차를 그대로 사용합니다. 기존 `ENCRYPTION_KEY`를 유지해야 저장된 협업 본문과 첨부를 읽을 수 있습니다.

```bash
npm ci
npm run db:setup
npm run build
npm start
```

`db:setup`은 PostgreSQL과 SQLite 모두에 `collaboration_records`, `collaboration_files` 테이블을 추가합니다. 기존 접수 테이블은 변경하지 않습니다. Cloud Run 자동 배포는 기존 DB 설정 Job으로 테이블을 만든 후 서비스를 갱신하는 절차를 사용합니다.

운영 배포 전 기존 절차에 따라 DB 백업을 확보합니다. 이전 앱 버전으로 되돌려도 추가된 테이블을 삭제하지 않으며 기존 접수 기능과 데이터는 유지됩니다. 협업 기록·첨부도 Cloud SQL 백업 범위에 포함됩니다.

## 검증

`npm run typecheck`, `npm test`, `npm run build`를 사용합니다. 협업 통합 테스트는 별도의 임시 SQLite와 서버로 실제 로그인, 권한 차단, 8개 분과 자동 생성, 동시 수정 충돌, 가져오기 원자성·중복 방지, 암호화 저장, 첨부 업로드·다운로드, 로그아웃을 검증합니다. 운영 DB나 실제 구성원 데이터를 사용하지 않습니다.

## 채팅 바로 입장

`/chat`은 로그인 후 대화 탭을 먼저 엽니다. `chat.segokwyd.kr`의 루트 주소에서도 채팅을 먼저 엽니다. 홈페이지의 상단·하단 협업 메뉴는 제거했습니다. 회의록과 문서함은 협업 공간 내부에서 이동할 수 있습니다. 도메인 연결 절차는 [채팅 도메인 연결](CHAT_DOMAIN.md)을 참고하세요.

## 기존 엑셀 회의록 가져오기

일반 운영자 이상은 상단 **엑셀 회의록 가져오기**에서 기존 WYD 공동회의록 양식의 `.xlsx` 파일(12MB 이하)을 선택합니다. 공동회의록과 8개 분과 시트가 있는 양식을 지원하며 PDF, 한글, 구형 `.xls` 또는 임의의 엑셀 양식은 자동 변환하지 않습니다.

회의 제목·일시·장소·참석자와 분과 작성자·진행사항·논의·협조 요청 팀·결정 사항·향후 계획, 후속 업무를 읽습니다. 미리보기에서 내용을 확인·수정한 뒤 **새 회의로 저장**하면 8개 분과 기록과 연결 업무가 한 번에 저장됩니다. 날짜나 시간을 읽지 못한 경우 직접 입력해야 합니다. 원본 파일은 자동 보관되지 않으므로 필요하면 문서함에 별도 업로드합니다.

분과 시트의 작성란을 우선하며 공동회의록에 직접 입력한 값은 분과 작성란이 비어 있을 때 가져옵니다. 수식은 실행하지 않으며 분과 작성란에 수식이 있는 경우 마지막 저장 결과만 사용하고 안내합니다. 공동회의록의 수식 캐시를 빈 분과 기록 대신 사용하지 않습니다. 기존 회의는 덮어쓰지 않으며 같은 제목·날짜의 회의가 있는 경우 중복 가능성을 안내합니다. 동일 파일을 다시 선택해 저장하면 별도 회의가 생성될 수 있습니다. 후속 업무는 100개까지 지원합니다.

## 새 대화·답글과 업무 기한 알림

상단 **알림**은 다른 구성원의 미읽음 대화·답글과 미완료 업무 중 기한이 지났거나 3일 안에 마감되는 항목을 보여줍니다. 내 대화에 달린 답글은 별도로 표시합니다. 항목을 누르면 해당 채널·답글 또는 담당 분과의 업무 화면으로 이동합니다. 채널 옆 숫자는 그 채널의 미읽음 메시지 수입니다.

대화 채널을 열어 최신 메시지까지 확인하면 자동으로 계정별 읽음 상태를 저장하며 채널 숫자와 대화 알림이 사라집니다. 채널은 최신 메시지 위치에서 열리고, 아래쪽을 보고 있을 때 새 메시지가 오면 최신 위치로 이어집니다. 예전 대화를 위로 스크롤해 읽는 동안에는 새 메시지를 자동으로 읽음 처리하지 않습니다. 다른 화면·숨겨진 탭·검색 중에는 읽음 처리하지 않습니다. 별도의 읽음 처리 버튼은 없습니다. 이후 들어온 메시지는 다시 표시됩니다. 다른 기기에서도 같은 계정의 읽음 상태를 사용합니다. 알림은 사이트 안에서 확인하며 이메일이나 휴대전화 푸시를 보내지 않습니다. 업무 기한은 한국 날짜를 기준으로 판단합니다.

## 수정 이력과 복원

회의 정보·분과 기록·후속 업무·공유 문서의 **수정 이력**에서 이전 버전과 작성자, 수정 시각을 확인합니다. 이전 버전을 펼쳐 내용을 검토한 뒤 **이 버전으로 복원**을 누르면 새 버전으로 저장합니다. 복원 전 내용도 이력에 남습니다. 다른 구성원이 먼저 수정했다면 복원을 중단하고 최신 내용을 다시 확인하도록 안내합니다.

이 기능 적용 이후 수정부터 이전 내용을 보관합니다. 과거에 이미 덮어쓴 내용은 소급 복구할 수 없습니다. 읽기 전용 구성원은 이력 확인만 가능하며, 이전 버전이 현재 접근할 수 없는 분과에 속하면 보여주지 않습니다. JSON 기록 백업에는 수정 이력·권한 설정·개인 읽음 상태가 포함되지 않으며 서버 DB 백업으로 보관합니다.
